# Founder Documentary / Shareable Endings v0.1

## Overview

The Founder Documentary transforms every completed startup run into a cinematic, shareable war story. Instead of ending at a score screen, every finalized startup receives a personalized documentary-style record built entirely from in-game data.

Every documentary is deterministic and generated entirely in-game. No external APIs, no LLM calls, no social posting, no analytics SDKs, no secrets.

---

## How to Access

- **From the startup profile**: "View Founder Documentary" link in the Final Result section
- **From the action bar**: STORY tab (available for all startups, navigates to `/startup/[id]/documentary`)
- **Direct URL**: `/startup/[id]/documentary`

| Field | Type | Description |
|---|---|---|

| `careerImpactSummary` | DocumentaryCareerImpactSummary \| null | Career impact (if career profile) |

### DocumentaryTone

| Value | When applied |
|---|---|
| `triumphant` | BREAKOUT with score ≥ 700 or SERIES_A_READY |
| `underdog` | BREAKOUT with score < 700 |
| `legendary` | ACQUISITION or ACQUIHIRE |
| `chaotic` | Hype Machine dominant strategy |
| `gritty` | Dead/failed after 9+ months, or long non-best run |
| `tragic` | Dead with rivals that were never defeated |
| `cautionary` | Dead/failed with high risk score (≥85) or short run |
| `satirical` | Regulated Operator dominant strategy |

### DocumentaryGenre

| Value | When applied |
|---|---|
| `founder_memoir` | Breakout/Series A without rivals, or long failed run |
| `arena_highlight` | Breakout/Series A with rivals |
| `startup_true_crime` | Dead/failed with short survival (< 9 months) |
| `investor_case_study` | Acquisition or Acquihire |
| `comeback_story` | Win outcome with rivals present |
| `cautionary_tale` | Other non-win outcomes |

## Generation Inputs

The documentary is generated from:

1. **Startup record** — name, sector, region, problem, solution, status, final outcome/score/reason, simulationMonths, fundingRounds, employees, missions, aiAnalysis (strategyArchetype)
2. **SocialState** — hype/trust/brandRisk metrics, feedItems (Arena Feed), actionsTaken, rivalProfiles, rivalMoveHistory
3. **FounderProfile (career)** — founderTitle, founderRank, reputationScore, recentRuns (for per-run reputation delta)

No external systems are queried. All inputs come from existing Prisma-persisted game state.

---

## Deterministic Copy Rules

- **Title**: Selected from outcome-specific pool using `djb2(startupId) % poolSize`. Same startupId always produces the same title.
- **Tagline**: Selected from tone-specific pool using `djb2(startupId + 3) % poolSize`.
- **Chapters**: Generated by composing real startup data into template sentences. No random selection in chapter bodies — same data always produces same text.
- **Timeline**: Selected by importance score (see Timeline section). Deterministic for same input.
- **Share text**: Composed from startup data fields. No randomness.

---

## Chapter Generation (3–6 chapters)

Chapters are always generated in this order. Optional chapters are omitted if source data is absent.

| # | Category | Required | Source |
|---|---|---|---|
| 1 | `origin` | Always | startup.name, sector, region, problem, solution, fundingAsk |
| 2 | `funding` | Always | startup.fundingRounds, investorScore trend |
| 3 | `strategy` | If strategyArchetype present | aiAnalysis.strategyArchetype (written by Phase 9C) |
| 4 | `social` | If socialState.actionsTaken.length > 0 | socialState metrics + top feedItem |
| 5 | `rival` | If socialState.rivalProfiles.length > 0 | rivalProfiles, rivalMoveHistory |
| 6 | `verdict` | Always | finalOutcome, finalScore, months, deathReason |

Copy style rules:
- No motivational filler ("You did great!"). Sharp, game-like, factual.
- No invented events. Every sentence references real data.
- Concise: each chapter body is 2–4 sentences.
- No emojis.

---

## Timeline Moment Selection

Timeline moments are extracted from:

| Source | Criteria |
|---|---|
| Launch (month 1) | Always included |
| Funding rounds | Each funding round gets a moment (approximated month) |
| First revenue | First month where revenue > 0 |
| Product milestones | When productProgress crosses 50% or 80% |
| Risk spikes | When riskScoreAfter ≥ 80 AND spike > 15 points |
| Investor collapse | When investorScoreAfter ≤ 20 AND dropped from > 30 |
| Named events | Each simulationMonth with eventTitle |
| Runway warnings | When runwayMonths ≤ 2 |
| Social critical/viral | Top 3 feed items with severity=critical or category=viral |
| Rival critical moves | Top 2 rival moves with severity=critical or warning |
| Final outcome | Always included |

**Importance scoring:**
- Final outcome: 100
- Funding rounds: 85
- Critical rival moves: 80
- Runway warnings: 75
- Social critical: 72
- Risk spikes: 70
- Investor collapse: 68
- First revenue: 65
- Social positive/viral: 60
- Named events: 60
- Product milestones: 55–58
- Launch: 30

**Selection:** All moments collected, pinned moments (launch + final) always kept, remaining sorted by importance, top 8 taken, merged with pinned, then trimmed to max 10, sorted by month.

## Share Card Behavior

The share card is a visually styled UI card (screenshot-friendly, dark background) showing:

- Founder Arena header
- Startup name + founder title + sector
- Outcome badge
- Score / Valuation / Months (3-column grid)
- Strategy archetype badge (if available)
- Badge line (if reputation delta > 0 or badges earned)
- Documentary tagline as a quote

**Copy Share Text**: Clicking "COPY SHARE TEXT" copies a plaintext multi-line string to the clipboard using the Web Clipboard API. No external services called. No platform-specific sharing. Text is composed locally from game state.

Share text format:
```
FOUNDER ARENA // RUN COMPLETE

{StartupName} — {Sector} | {Region}
Outcome: {OUTCOME_LABEL}
Score: {score} | Valuation: {valuation} | {weeks} Founder Weeks
Strategy: {PlaystyleDisplayName}   ← only if present

"{documentary tagline}"
```

## Final Result Integration

The documentary does not replace the existing final score/result section. It is an additional layer linked from:
1. Final Result section: "View Founder Documentary" link (prominent, cyan)
2. Action bar: STORY tab (8th tab at `/startup/[id]/documentary`)

The documentary page shows a "not available" state for startups that are not yet finalized.

---

## Persistence Model

**Decision: Compute on read (no new DB fields).**

The documentary is recomputed from existing persisted state every time the documentary page is viewed. This is safe because:
- Startup is finalized (status=dead/completed) — simulationMonths do not change
- `aiAnalysis.strategyArchetype` is written by finalize-startup.ts (Phase 9C) at finalization
- SocialState is not modified after finalization
- Career profile is read-only for this purpose (no writes from documentary)

The same startup always produces the same documentary because all generation functions are deterministic from their inputs.

**Trade-off**: No "generation timestamp" or "snapshot at finalization time" is stored. If the generation logic changes in a future phase, existing startups will see updated documentaries on next view. This is acceptable for v0.1.

## Career Integration

The documentary reads from the career profile:
- `founderTitle`, `founderRank`, `reputationScore` — current values
- `recentRuns[startupId].reputationDelta` — per-run reputation delta
- `legacyBadges.length` — total badge count

The career profile is not updated or written by the documentary system. Career updates remain the exclusive responsibility of `lib/game/career-record.ts` (Phase 10).

---

## Strategy Integration

The strategy archetype is read from `startup.aiAnalysis.strategyArchetype`, which is written by `finalize-startup.ts` (Phase 9C) at finalization time. This includes:
- `dominantPlaystyle`
- `secondaryPlaystyle`
- `finalRunNarrative` — used as the strategy chapter body
- `strengths`, `weaknesses` — shown in the strategy panel

If no strategy data exists (startup predates Phase 9C, or strategy system never triggered), the strategy chapter and strategy panel are omitted.

---

## Rival Integration

Rival data is read from `socialState.rivalProfiles` and `socialState.rivalMoveHistory`. These are written by Phase 9B (Rival Founder / Nemesis System) during simulation.

Documentary uses:
- Rival count and defeat count for summary stats
- Highest-rivalryScore rival for "strongest rival" callout
- Top critical rival move for chapter and timeline

If no rivals exist (startup predates Phase 9B, or no rivals spawned), the rival chapter and rival panel are omitted.

---

## Social Integration

Social data is read from `socialState.feedItems`, `socialState.actionsTaken`, and social metrics (hype, trust, brandRisk). These are written by Phase 9A (Social Media & Arena Feed).

Documentary uses:
- `actionsTaken.length` to determine if a social chapter exists
- Feed items for top moment extraction (viral/crisis)
- Final social metrics for the social summary panel

If no social actions were taken, the social chapter and social panel are omitted.

## iOS Port Notes

The documentary engine (`lib/documentary/`) is pure TypeScript with no Next.js or React dependencies. To port to iOS SwiftUI:

1. **Port `lib/documentary/types.ts`** → Swift structs/enums
2. **Port `lib/documentary/documentary-engine.ts`** → Swift functions using the same djb2 hash and pool-pick logic
3. **Port `lib/documentary/documentary-timeline.ts`** → Swift pure functions over equivalent data models
4. **Port `lib/documentary/documentary-share-card.ts`** → Swift struct builder

The UI (`documentary-client.tsx`) should be reimplemented natively in SwiftUI using the same data shape from the engine output.

Share functionality on iOS: use `UIActivityViewController` instead of Web Clipboard API.

The domain models are designed to be serializable (no functions, no closures, simple value types) to ease JSON transport if the iOS app fetches documentary data from the API.

## Known Limitations (v0.1)

1. **No generation timestamp**: Documentary recomputes on every page view. If copy changes, existing startups see the new version.
2. **Funding round months are approximated**: FundingRound model does not store which game month it was raised. Timeline uses index+2 as approximation.
3. **Per-run badge unlocks not persisted**: The career record stores cumulative badges but not which badges were unlocked per-run. The documentary shows total badge count but cannot say "you earned X badge this run" from a later page view.
4. **No screenshot-to-image export**: The share card is screenshot-friendly UI, not a programmatic image. Actual image generation was explicitly excluded.
5. **Short chapters**: Chapter bodies are 2–4 sentences. Long-form narrative is not generated (per spec: no LLM calls).
